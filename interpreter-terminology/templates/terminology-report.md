# 术语研究 / 测试交付报告模板（terminology-report.md）

用于**研究/核验**类交付，测试类报告见 §B。结构为 Markdown，可读可导出。

---

## §A 术语研究 / 核验报告

采用最终交付结构：

```
主题知识概览 → 核心术语 → 易混淆术语 → 高频搭配/表达 → 真实语料 → 来源
```

**贯穿全程的规则（R2/R7，verification-rules.md §3bis）：**
- **来源与内容一一对应**，在每段内容旁内联标注来源，而非文末统一列一堆。
- 来源必须给 **可直接点击的原始链接（URL）**，支持**多个来源**并列，不只手写来源名称。
- 无法给出真实 URL / 无法核验的内容 → 明确标注 **"未核验"** 或 **"AI生成内容"**，绝不伪装成事实。
- 无联网时整体标注"本环境未做在线核验，来源待补充"，且不附任何虚构链接。

---

### 1. 任务画像

- 语言方向：source → target
- 主题 / 领域 / 子领域 / 场景 / 受众
- 涉及的机构 / 人物 / 政策（按需）
- 目标术语数量：N
- 核验说明：本次是否有联网核验（R7 如实标注）

### 2. 主题知识概览（先于术语表）

按模块组织，**每个重要事实/数据/政策/事件/定义紧跟在来源链接**（见 topic-overview.md）：

```
### ① 主题背景与基本概念
- 概念界定……（来源：[机构/文件](URL)）
- ……（来源：[…](URL)、[…](URL)）   ← 多来源并列

### ② 发展现状 / 相关事件
- 关键时间点 / 里程碑 / 近期动向……（来源：[…](URL)）
- 未核验的信息 → 明确标注"（未核验）"或"（AI生成）"

### ③ 核心议题与关键概念
### ④ 相关机构 / 政策 / 行业背景
### ⑤ 本次口译需重点理解的内容
```

### 3. 核心术语（按 P1→P2→P3 顺序）

每个术语卡片，**来源直接内联、可点击、可多个**：

```
### 术语（source → target）──────── P1
- 权威注记（官方定义 / 权威释义，**必须带可点击链接**）：
    - 释义……（来源：[术语库/官方文件 1](URL1)  ·  [来源 2](URL2)  ·  核验日期）
- 搭配：……（来源：[…](URL)，如有）
- 同义/变体/缩写：……
- 例句：
    - [real] 原文……（[来源](URL)）
    - [ai_generated] ……（注：AI生成，仅用于练习）
- 核验状态：verified / multi-source / single-source / conflict / pending / ai-candidate
    - 若 conflict：并列多版本 + 各自来源链接 + "本次建议优先使用 X，因为……"
- 个人版本（若存在）：user_version
```

> **每个专业词汇的权威注记都附可点击原始链接**（可多个来源并列）；未核验或 AI 候选的词，卡片中显著标注"尚未完成权威来源核验"，无真实 URL 则不附链接。

### 4. 易混淆术语

并列较近义词 / 上下位词 / 易误译词，每组各词绑定自身来源链接，并说明区分要点。

### 5. 高频搭配 / 表达

列最常见的专业搭配与固定表达，每个搭配绑定其出现来源（可多个可点链接）。

### 6. 真实语料

摘录官方文件 / 权威来源中的真实句子（`real`），每条带原文、来源名称、可点击 URL；必要时给出对应术语与中文/目标语提示。

> 若为练习而生成示例句，单独归到 AI 例句，标注"AI生成，仅用于练习"，不混入真实语料。

### 7. 来源核对与待办

- 凡标记 `conflict` / `pending` / `ai-candidate` / "未核验" 的内容，逐个列原因与待办（补来源 / 用户决定）。
- 最终确认：无任何"应绑定却未绑定、或虚构链接"的内容。

### 8. 入库结果与下一步建议

- 入库：新增 N 条、更新 M 条、跳过重复 K 条；是否覆盖用户版本：无（R3）。
- 建议复习的词、可进入场景口译的议题、待用户确认项。
