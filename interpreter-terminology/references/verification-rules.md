# 核验与反幻觉规则（verification-rules.md）

本文件规定了 R2（不编造）、R4（不伪装官方）、R5（真实语料分离）的逐条可执行规则，以及 `verification_status` 的判定与冲突处理。

---

## 1. 绝对禁止编造（R2）

禁止虚构：专业术语、官方译法、官方文件、机构名称、数据库、词典、URL、引文、真实语料、来源、来源原文。

判定标准：
- 一个"来源"只有在你**实际访问到**并能给出原文/准确定位时才存在。
- **找不到可靠来源 → 明确标 `ai-candidate`**，并向用户说明："当前表达为 AI 候选译法，尚未完成权威来源核验。"
- 宿主无联网能力 → 如实说明"本环境未做在线核验"（R7），不补造任何来源。

---

## 2. 来源核验状态 `verification_status`

| 状态 | 判定条件 |
|---|---|
| `verified` | 已通过可靠来源核验，表达明确成立。 |
| `multi-source` | 多个可靠来源使用相同或高度一致的表达。 |
| `single-source` | 目前仅一个可靠来源。 |
| `conflict` | 不同来源存在不同表达（见 §3）。 |
| `pending` | 尚未完成核验（如无联网、检索未进行）。 |
| `ai-candidate` | AI 候选表达，无可靠来源支持。 |

**同一条术语**保存：`verification_status`（最终判定）+ 每条来源各自的状态（便于审计）。如字段不够可扩展，但不得移除 `verification_status` 与来源证据。

---

## 3. 来源冲突处理

当 A 来源用 X、B 来源用 Y 时，**不得告知"X 才是唯一正确答案"**。应并列展示各版本：

```
表达 A
  来源：……
  适用场景：……

表达 B
  来源：……
  适用场景：……
```

然后，**结合本次口译场景**给出推荐："建议优先使用 X，因为……"，但保留并展示其他版本。`verification_status = conflict`。

⚠️ 冲突也必须基于真实来源。若两边都不是可靠来源，应标 `ai-candidate` 而非 `conflict`。

---

## 3bis. 来源与内容一一对应，可点击直达

**结构目标**：`具体内容 → 对应来源 → 点击即可核验`，而**不是** `大量内容 → 页面底部统一列一堆来源`。

- 每个术语、每个事实/数据/政策/事件/定义，都在**旁侧内联**标注来源，而非只在文末汇总。
- 来源必须给出 **可直接点击的原始链接（URL）**，不得只显示来源名称。
- 同一内容由多个来源共同支持 → **显示多个来源**，并列可点。
- `source_url` 必须指向 **实际可访问、可验证** 的页面；无法给出真实 URL 的内容，宁可标注"未核验"，**不得虚构链接**（R2/R7）。
- 来源链接的可点击性与真实性，同时适用于：主题知识概览（见 topic-overview.md）、术语卡片、真实语料、易混淆术语、高频搭配。

---

## 4. 真实语料与 AI 例句严格分离（R5）

例句必须带类型标签：

```json
{
  "example_type": "real" | "ai_generated"
}
```

### `real`（真实语料）
必须保存：原文、来源、URL。例：

```json
{
  "example_type": "real",
  "text": "原文……",
  "source": "……",
  "url": "https://..."
}
```

### `ai_generated`（AI 生成，仅用于学习）
必须明确标注："AI生成，仅用于练习，不代表真实语料。"例：

```json
{
  "example_type": "ai_generated",
  "text": "……",
  "notice": "AI生成，仅用于练习，不代表真实语料。"
}
```

**绝对禁止把 AI 生成的句子伪装成真实语料。**

---

## 5. 重新核验时的守则（配合 R3）

- 重新检索发现"用户个人版本 ≠ 最新来源"时：
  - **不自动覆盖 `user_version`。**
  - 展示：当前个人版本 / 新来源版本（含来源与 URL）/ 差异 / 使用场景。
  - 让用户决定是否更新。
- 若新来源状态由 `verified` 变成 `conflict`，同样提示用户，不强行改判。
