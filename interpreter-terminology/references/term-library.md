# 个人术语库维护（term-library.md）

本文件规定个人术语库的**存储、检索、增改、导入导出、合并去重**。核心原则：先查库（R6）、不覆盖用户数据（R3）、保留来源、保护个人版本。

> **存储格式不写死。** 优先使用机器可读的 JSON；若宿主支持文件系统，按实际能力选择 JSON / CSV / Markdown / TXT，必要时可由宿主关联 Excel。本文件给出通用规则而非固定实现。

---

## 1. 检索（研究前必做）

新研究开始前，先在个人术语库检索：精确匹配、同义词、相关词、词根、中文关键词、外语关键词、`topic`、`field`、历史记录。

命中时的展示优先级：
1. 用户个人版本（`user_version` 存在时优先展示）；
2. 否则展示 AI 原始版本；
3. 附上其 `verification_status`、`mastery`、错误记录。

然后判断是否需要重新外部核验：来源过期、状态为 `pending`/`ai-candidate`、或用户主动要求重核。

---

## 2. 增改（入库）

- 新增词条时与库内现有词条比对（见 §3），避免重复入库。
- 用户修订 → 只写 `user_version` + `user_note`，保留 `ai_version` 与来源证据。
- **重新检索结果与用户版本不一致时，不自动覆盖**，按 SKILL.md §7 展示对比，由用户决定（R3）。

---

## 3. 去重与合并

判定重复的依据（命中其一即提示合并）：
- `source_term` + `target_term` 完全一致；
- 同义词/变体高度相近；
- 相同或近似 `field`/`topic` 且词项一致。

合并守则：
- **不覆盖已有个人数据**（R3）。
- 合并时保留双方来源；若表达不同，进入 `conflict` 展示，不自动选边。
- 新检索到的来源可并入已有词条的来源列表，更新其 `verification_status`（仅限状态升格有依据时：如 single-source → multi-source），但不得把 `user_version` 一并覆盖。

---

## 4. 导入

支持 JSON / CSV / Markdown / TXT（宿主支持时的补充：Excel）。

导入流程：
1. **自动识别字段**：尽量映射到 term-schema（未知字段放侧栏或记为 tags）。
2. **检测重复**：见 §3 判定规则。
3. **合并**：已有条目保留个人版本，新数据并入缺失字段。
4. **保留来源**：导入内容带来源的，原样保留；不带来源的，`verification_status` 记为 `pending`。
5. **不覆盖**：已有 `user_version` 的词条，导入数据不得覆盖它。

---

## 5. 导出

可导出为 JSON（完整）/ CSV（平铺核心字段）/ Markdown（人类可读报表）/ TXT（纯文本）。导出格式：
- 保留 `verification_status`、来源、`user_version`/`ai_version`、`mastery`。
- 可选按 `topic`/`field`/`priority`/`target_language` 过滤导出。

---

## 6. 备份建议

术语库是长期资产。若宿主支持文件系统，建议：
- 保持可版本化的纯文本/JSON 存储；
- 导出到用户指定的备份目录；
- 不把个人库内容写成对外不可逆格式（例如不依赖私有数据库或云端格式）。
