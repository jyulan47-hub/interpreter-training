# 主题知识概览（topic-overview.md）

在**术语表之前**生成一份该领域背景知识的检索式总结。它的工作方式 = **把主题当成检索关键词，像做一次检索那样，把整个领域的背景知识汇总成一份有条理的知识摘要**，帮用户先建立对主题的**知识框架与背景理解**，再进入"这个概念怎么表达"。

目标顺序（Skill 的最终交付结构）：
```
主题知识概览 → 核心术语 → 易混淆术语 → 高频搭配/表达 → 真实语料 → 来源
```

---

## 1. 概览必须包含的模块

按用户提供的口译背景/会议主题/场景生成，至少覆盖：

| 模块 | 内容 | 示例（中→法，欧盟 AI 监管） |
|---|---|---|
| ① 历史沿革与主题背景 | **历史背景、来龙去脉**、这个领域怎么来的、基本概念与范畴 | 从 AI 治理萌芽到 AI Act 立法的必要性与动因 |
| ② 发展现状 / 相关事件 | 关键时间点、里程碑、近期动向、行业现状 | AI Act 立法历程、适用节奏、关键事件 |
| ③ 核心议题与关键概念 | 本领域最关键的问题、阵营、争议点 | 高风险系统、基础模型、执法与标准 |
| ④ 相关机构 / 政策 / 行业背景 | 监管/行业主体、政策脉络、行业影响 | 欧盟委员会、AI Office、欧洲议会 |
| ⑤ 本次口译需重点理解的内容 | 结合会议场景的翻译要点 | 哪些概念最可能被反复提到、易混淆 |

**核心目的：先给背景，再给表达。** 概览要让译者**先对这个主题的知识整体建立认知**，再进入"这个概念怎么讲"。因此 **① 历史沿革与主题背景是必需的**——它回答"这个领域/这件事从何而来、为什么重要"，为后续术语理解提供知识落点。

**性质：** 概览应**像一份"领域背景知识检索总结"**——简洁、有条理、恰好够让译者对该领域有整体把握，但**紧扣本次口译场景，不是堆砌百科全文**。历史背景只呈现与本次口译相关、能帮助理解的部分，不无目的地追溯典故。

## 2. 概览的可考证要求（核心规则）

概览中的**每个重要事实、数据、政策、事件、定义、机构定位**必须与来源**一一对应**，且来源为**可直接点击的原始链接**。

### 2.1 绑定方式

在句/段旁边内联给出来源链接，而不是集中在文末。例如：

> EU AI Act 于 2024 年 8 月正式生效（← [欧盟官方：Regulation (EU) 2024/1689](https://eur-lex.europa.eu/…)）。

- 每个事实紧跟其来源；同一事实可由多个来源共同支持 → **显示多个来源**。
- 结构要求：**具体内容 → 对应来源 → 点击即可核验**，而非"大量内容 → 底部统一列一堆来源"。

### 2.2 来源优先级

政府及官方机构 → 国际组织 → 专业术语库（IATE / TERMIUM Plus 等）→ 官方文件/法规/标准 → 高质量学术/专业机构资料。（详见 terminology-sources.md）

### 2.3 反虚构

- **不得虚构**来源、数据、链接、政策条文、事件时间。
- 链接必须指向**实际可访问、可验证**的页面；无法给出可靠 URL 时，宁可标注而不编造。
- 无法可靠核验的信息 → 明确标注 **"未核验"** 或 **"AI生成内容（待核验）"**，绝不伪装成事实。
- 宿主无联网能力 → 概览整体标注"本环境未做在线核验，以下为 AI 生成背景，来源待补充"，且不附任何虚构 URL（R7）。

---

## 3. 与术语研究的关系

- 概览先于术语表生成；术语表随后的"真实语料"通常就是概览所依据的官方文件中摘出的句子，两者来源可呼应。
- 概览为术语提供了语境：一个词出现在概览的哪个议题里，可快速定位到对应术语卡片。
- 概览本身也用于生成"易混淆术语"——通常是被反复提及、语义相近或官方文件中并列出现的概念。

---

## 4. 与铁律的对接

- R2（不编造）/ R4（伪装）：概览的事实、数据不得编造，来源必须真实可点击。
- R5（真实语料分离）：概览中若引用原句，属 `real`，必须带来源；若为解释性改写，属 AI 生成，面向用户标注。
- R7（工具不可用不假装）：无联网 → 概览整体标注"未在线核验"。
- R8（只做用户要的）：概览篇幅受控，紧扣本次会议主题，不为凑内容展开无关背景。
