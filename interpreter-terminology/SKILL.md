# 口译术语研究与记忆训练（interpreter-terminology）

一个专业的口译术语闭环系统：**研究 → 核验 → 入库 → 修改 → 积累 → 测试 → 发现薄弱项 → 复习 → 再次口译 → 继续积累**。

本 Skill 只负责**判断何时调用宿主能力、以及如何处理结果**。它不内置任何搜索、数据库、浏览器或文件系统实现；具体工具由宿主环境（Claude Code / Codex / Trae / WorkBuddy 等）提供。

---

## 0. 本 Skill 的铁律（违反任何一条都视为错误）

| # | 铁律 | 说明 |
|---|------|------|
| R1 | **不强制三语** | 绝不为所有词都配"中英法"。只按用户实际口译方向产出 `source_term` 与 `target_term`，语言字段全部动态化。 |
| R2 | **不编造** | 禁止假装核验、禁止虚构来源/官方译法/URL/引文/真实语料。找不到可靠来源时，标记 `ai-candidate` 并明示。 |
| R3 | **不覆盖用户数据** | 用户修改过的内容（`user_version`）永不被自动覆盖。重新核验发现差异时，只展示对比并让用户决定。 |
| R4 | **不把 AI 候选伪装成官方译法** | AI 生成的译法只能作为候选列在最后，不得冒充权威来源。 |
| R5 | **真实语料与 AI 例句严格分离** | 真实例句必须带来源+URL；AI 例句必须标注"AI生成，仅用于练习"。 |
| R6 | **先查个人术语库** | 任何新研究开始前，先检索用户的个人术语库，命中则优先展示个人版本。 |
| R7 | **工具不可用就不假装** | 宿主没有联网/搜索能力时，如实说明"未做在线核验"，不得编造核验结果。 |
| R8 | **只做用户要的** | 用户要求 100 词，不硬堆 200 词凑数；先保证 P1/P2 质量再扩展 P3。 |

## 1. 何时触发

以下自然语言请求（及同类表达）都应触发本 Skill：

- "帮我准备这个主题的口译术语"
- "研究一下这个会议涉及哪些专业词汇"
- "帮我查这个词在法语里的专业译法"
- "检查这个译法是否权威"
- "加入我的术语库" / "搜索我的术语库"
- "测试我今天的术语" / "只测试我容易错的词"
- "根据我的术语库做一套中法口译模拟"
- "重新核验这些术语" / "导出这个主题的术语表"

如果请求不属于上述范围（例如仅翻译一句话、解释概念），则不要调用本 Skill。

## 2. 语言方向协议（R1 的具体执行）

**不要默认中英法三语。** 每次必须先确定方向，再按唯一方向研究。

| 用户口译方向 | source | target | 产出 |
|---|---|---|---|
| 中 → 法 | 中文 | 法语 | 中文术语 → 法语专业表达 |
| 法 → 中 | 法语 | 中文 | 法语术语 → 中文专业表达 |
| 中 → 英 | 中文 | 英语 | 中文术语 → 英语专业表达 |
| 法 → 英 | 法语 | 英语 | 法语术语 → 英语目标表达 |
| 英 → 法 | 英语 | 法语 | 英语术语 → 法语目标表达 |
| 自定义 | 任意 | 任意 | 按用户指定 |

数据结构中语言一律动态，永不写死为固定枚举：

```
source_language
target_language
term_language      （术语本身的语言标签，用于真实语料/搭配）
definition_language（定义所用语言）
learning_language （学习与测试提示所用的语言，通常默认为用户母语）
```

**方向确定规则：**
- 用户明确说了方向 → 直接采用。
- 从上下文（主题/场景/机构/用户母语）可稳妥推断 → 采用并告知。
- **方向无法确定，且方向会影响检索结果** → 询问用户（一次即可），不得擅自猜测。

额外语言（英语/其他）可以**按需补充**（例如作为同义词、国际通用名），但不默认、不强制、不堆砌。

## 3. 任务分析（每次研究的第一步）

在检索任何词之前，先输出一份内部"任务画像"（不一定要给用户看，但决定检索策略）：

```
source_language:   中
target_language:   法
field:             法律 + 科技 + 政策
topic:             欧盟人工智能监管
scenario:          国际会议 / 政策讨论
audience:          政府官员与政策研究者
institutions:      欧盟委员会、欧洲议会、AI Office
products/policies: EU AI Act ...
required_terms:    30
has_library:       true  → 先搜个人术语库
```

至少要从用户输入中推断：语言方向、主题、行业、专业领域、子领域、场景、受众、会议/活动背景、可能机构、可能人物、可能的产品/技术/政策/法规、所需术语数量、已有术语库情况。信息不足且影响结果时，只补问关键信息，不要连环追问。

## 4. 主工作流

每次请求按以下流程执行。步骤可因请求类型（研究/测试/导出）跳过或精简。

### 4.1 分析（见 §3）
输出任务画像，确认语言方向与主题范围。

### 4.2 检索个人术语库（R6）
在个人术语库中检索：精确匹配、同义词、相关词、词根、中文/外语关键词、`topic`、`field`、历史记录。
- 命中 → 优先展示用户个人版本。
- 然后判断：是否需要重新外部核验（来源过期、状态为 `pending`/`ai-candidate`、或用户主动要求）。

### 4.3 产出术语候选清单
按优先级排序产出（见 §6），不要一次性铺 100 词。先给最核心的一批，质量优先。

### 4.4 外部权威检索与核验（仅在宿主具备联网能力时）
- 调用宿主提供的 Web Search / Browser / 网页抓取 等工具。
- 严格按"来源优先级"和质量过滤（见 references/terminology-sources.md）。
- 逐条记录来源、原文引用、URL、日期。
- 为每个词写 `verification_status`（见 references/verification-rules.md）。
- **没有联网能力 → 全部标 `pending` / `ai-candidate`，如实告知"未做在线核验"。**（R7）

### 4.5 生成结构化术语卡片
按 references/term-schema.md 的结构生成。入库前允许用户修改（user_version / ai_version 分离，见 §7）。

### 4.6 生成主题知识概览（先于术语表）
- 基于任务画像（§3）与已核验来源，先产出主题背景与知识框架（背景/现状/核心议题/机构政策/本次口译重点）。
- 概览中的**每个重要事实、数据、政策、事件、定义都与来源一一对应**，提供可点击原始链接；无可靠来源的内容标注"未核验"/"AI生成"。
- 详细规则见 references/topic-overview.md、references/verification-rules.md §3bis。

### 4.7 交付报告
按 templates/terminology-report.md 的最终结构输出：
```
主题知识概览 → 核心术语 → 易混淆术语 → 高频搭配/表达 → 真实语料 → 来源
```
- 术语卡片（P1/P2/P3）、来源核验状态、冲突说明、待用户确认项。
- **来源逐条内联绑定到对应内容**，术语旁直接给可点击原始来源链接（可多个），不在文末统一罗列（verification-rules.md §3bis）。
- 如果本次只是"测试/复习"，跳到 testing-rules.md 的工作流。

### 4.8 记忆与训练（可选阶段）
生成记忆测试 / 场景口译训练，详见 references/testing-rules.md。**是否进入此阶段由用户决定**，不要强行附送测试。

## 5. 宿主工具的使用方式（不硬编码）

判断**当前宿主实际提供了哪些工具**，然后按其能力行事：

| 宿主能力 | 何时调用 | 约束 |
|---|---|---|
| Web Search | 搜索官方术语库、机构文件、权威来源 | 只取权威域名结果（见 terminology-sources.md） |
| Browser / 网页抓取 | 访问具体页面、读取定义原文 | 记录完整 URL 与访问日期 |
| PDF 阅读 | 解析官方文件/法规 | 原文引用需可定位 |
| 文件系统 / 本地存储 | 读写个人术语库（JSON/CSV/MD/TXT） | 见 references/term-library.md |
| 文档 / 表格 | 导入导出 Excel 等 | 仅当宿主支持时 |
| 计算 | 掌握度/复习计划计算 | 直接算，无需外部 |

**规则：**
- 本 Skill 只在"判断何时调用什么能力"方面起作用，不实现任何工具本身。
- 宿主没有某能力 → 明确告知用户"本环境无法执行 X"，不得假装完成（R7）。
- 不写死某个厂商 API、不要求固定 UI、不把 API Key / 密文写入本 Skill。

## 6. 术语优先级与分类

**排序依据**（分数从高到低决定顺序）：相关性 → 出现概率 → 专业性 → 误译风险 → 口译重要程度。

划分为：
- **P1 核心**：本次口译最可能直接用到、错译代价最高的词。
- **P2 重要**：高频但容错较高的专业词。
- **P3 扩展**：低频或边角词，数量受控。

**动态分类**：根据具体任务现场生成层级（如 `科技 → 人工智能 → AI治理`），不要依赖固定的预设分类表。

---

## 7. 用户修改机制（R3）

- 入库或交付时，用户可修改：词条、译法、定义、分类、来源、备注、例句、优先级。
- 用户确认的内容存入 `user_version`；Skill 原始内容存入 `ai_version`；两者并存，来源证据保留。
- 后续重新检索若发现"用户个人版本 ≠ 最新来源"，**不自动覆盖**，而是展示：

```
当前个人版本
新来源版本 + 来源 + URL
差异分析
可能适用场景
是否更新？（用户决定）
```

---

## 8. 交付与后续

- 报告结尾给出"待办"清单：待用户确认的冲突项、待补充来源的词、建议下次测试的词。
- 可提示进入记忆训练 / 场景口译，但把决定权交给用户。
