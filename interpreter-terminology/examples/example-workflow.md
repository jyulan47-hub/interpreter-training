# 端到端示例与测试用例（example-workflow.md）

说明 Skill 的**完整决策流程**，并给出 7 个验证用例，用于确认各项铁律是否被正确执行（可移植性检查项）。

---

## 一、一个完整工作流示例：中→法，欧盟 AI 监管

用户："帮我准备一个关于欧盟人工智能监管的中法会议口译。"

1. **分析（SKILL.md §3）**
   - source=zh，target=fr；field=法律+科技+政策；topic=欧盟AI监管；scenario=国际会议。
2. **查个人术语库（R6）**：检索 topic/filed/关键词 → 命中则优先展示个人版本。
3. **生成候选清单**：P1（如 algorithm 治理、沙盒、高风险系统、基础模型、透明度义务）、P2、P3（数量受控）。
4. **联网核验（若宿主支持）**：查欧盟 AI Act 官方文本、IATE、法国监管机构用语 → 记录原文/URL/日期 → 逐条定 `verification_status`。
   - 无联网 → 全部标 `pending`/`ai-candidate` 并如实告知（R7）。
5. **生成主题知识概览**：把"欧盟AI监管"当检索关键词，汇总领域背景知识（背景/现状/核心议题/机构政策/口译重点），每条事实行内绑可点击来源；无可靠来源标"未核验/AI生成"。
6. **生成术语卡片**（term-schema）→ 按 `主题知识概览 → 核心术语 → 易混淆术语 → 高频搭配/表达 → 真实语料 → 来源` 交付；每个词的**权威注记内联可点击链接**（可多个）。
7. **入库**（去重合并，不覆盖 user_version）→ 按需进入记忆/场景训练。

## 二、测试用例（用于验收 Skill 逻辑，非自动单元测试）

### Case 1 —— 中文 → 法语，主题：AI 监管
- 期望：所有卡片只有 zh→fr 两个主语言字段（R1）。不得出现默认英语。
- 检查：`source_term` 中文、`target_term` 法语、`definition_language` 与 `learning_language` 动态。

### Case 2 —— 法语 → 中文，主题：能源政策
- 期望：方向为 fr→zh，检索法语官方/机构来源 → 中文专业表达。不堆英语。

### Case 3 —— 中文 → 英语，主题：金融
- 期望：zh→en，查金融监管/机构权威来源 → 英文目标表达。不堆法语。

### Case 4 —— 已有个人术语库后重新研究同一主题
- 期望：**先查库（R6）**，命中词优先展示 `user_version`；对未变来源不必重复联网；仅对 `pending`/`ai-candidate`/过期的词重新核验。
- 检查：报告首节出现"来自个人术语库"。

### Case 5 —— 两个可靠来源存在不同译法
- 期望：进入 `conflict` 状态，并列展示两版本+各自来源，给出"本次建议优先 X，因为……"，**不得说 X 是唯一正确答案**。

### Case 6 —— 用户修改后重新核验
- 期望：新来源与用户版本不一致时，**不自动覆盖 `user_version`**（R3）；展示"个人版本/新来源/差异/适用场景"，由用户决定是否更新。

### Case 7 —— 主题知识概览与来源一一对应
- 期望：交付顺序为"主题概览 → 核心术语 → 易混淆 → 高频搭配 → 真实语料 → 来源"；概览每条事实和每个术语的**权威注记都内联可点击原始链接**（可多个），不走文末统一列表。
- 检查：无可靠来源的内容标注"未核验/AI生成"，无虚构 URL。

## 三、可移植性检查项（跨平台自检）

- [ ] SKILL.md 使用标准 `name` + `description` frontmatter（Claude Code / Codex / Trae / WorkBuddy 通用）。
- [ ] 语言字段全部动态，无"中文/英语/法语"硬编码枚举（R1）。
- [ ] 未硬编码任何厂商 API / 数据库 / 前端框架 / 固定 UI（§5）。
- [ ] 未写入任何 API Key 或密文（§5）。
- [ ] 无联能力时明确声明"未在线核验"，不假装（R7）。
- [ ] 用户版本永不被自动覆盖（R3）。
- [ ] 真实语料 / AI 例句明确区分（R5）。
- [ ] AI 候选不会伪装成官方译法（R4）。
- [ ] 主题知识概览先于术语表，且逐条内联可点击来源（topic-overview.md）。
- [ ] 每个专业词汇的权威注记带可点击原始链接，可多个（terminology-report.md §3）。
