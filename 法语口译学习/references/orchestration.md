# 编排决策（orchestration.md）

本 Skill 的唯一核心逻辑：**判断是否调用「译前准备」，然后调用对应训练 Skill**。

## 1. 是否需要译前准备？

| 依据 | 触发条件 | 判定 |
|---|---|---|
| 专业性 | 主题属专业知识门槛领域（医学、法律、金融、国际贸易、国际关系、AI、量子计算、能源、气候政策、航空、科技、经济、公共政策等） | 倾向"需准备" |
| 用户主动要求 | 明确说"先做译前准备 / 我不了解这个主题 / 不熟悉术语 / 先了解背景" | **必须**调用 |
| 用户水平 | CEFR 较低 + 主题专业强 | 建议先准备 |
| 历史数据 | 该主题历史多次出现术语/专名/背景/概念/遗漏错误 | 自动建议准备 |

综合判定：命中任一条强烈信号（用户主动要求=强制；多条弱信号叠加=建议）→ 提示做译前准备。

## 2. 调用链

```
需译前准备? ──否──→ 直接调用「french-interpretation-training」→ 练习
   │是
调用「interpreter-terminology」→ 得到主题背景/术语/双语表达/来源
   │
作为训练上下文 → 调用「french-interpretation-training」→ 练习
```

## 3. 用户交互（自然语言，不暴露 Skill/技术细节）

判定需准备时提示：
> 这个主题涉及一些专业背景，我先帮你做一个简短的译前准备，再开始训练。

给出选择：**先做译前准备** / **直接开始练习**。

- 选"先做译前准备" → 调用 `interpreter-terminology`，保存 `type: preparation` 记录，并把结果作为本次训练上下文（记录中写 `prep_called: true` + `prep_record_id`）。
- 选"直接开始练习" → 跳过译前准备，直接调用训练 Skill（`prep_called: false`）。

## 4. Skill 发现与调用

- 使用宿主当前实际支持的机制（可用技能清单 / Skill tool / manifest / dependency）。
- 目标 Skill 标识：`interpreter-terminology`（译前准备）、`french-interpretation-training`（口译/视译训练）。
- 发现失败 / 调用失败 → 明确告知用户，不得虚构成功，并提供降级建议（如：仅处理已有材料，不进行自动预备）。
