# 端到端示例与测试用例（example-workflow.md）

## 一、完整示例：法→中 口译，B2，自动搜索

用户："帮我做一段法译中、B2 的口译训练。"

1. **入口**：识别为 `interpreting`（无明确模式时先让用户选）。
2. **参数**：方向 fr→zh，CEFR B2（若未给则先推荐再由用户改），来源=自动搜索，时长 3–5 分钟。
3. **搜索材料**：随机主题（如"法国能源转型"）→ 找真实节目/报道 → 发布者、标题、URL、时间、语言、难度、时长、推荐理由。**无真实来源则改问用户上传**。
4. **背景/术语**：主题较专业 → **显式调用 interpreter-terminology** 拿主题概览+术语表；不可调用则明说。
5. **展示材料信息**（不提前给全文）。
6. **用户听并口译** → **ASR** → 用户修正 → 保存 ORIGINAL_ASR 与 corrected_transcript。
7. **评分**（B2 重点：信息/完整/逻辑重组/自然/术语/避免逐字）→ 反馈 → 普通/进阶参考译文。
8. **存档** + **更新个人错误库**。

## 二、测试用例（人工验收，非自动单测）

### Case A —— 无录音/无转写
- 期望：**不评分**，明示缺数据（R2）。

### Case B —— ASR 明显识别错误
- 期望：区分 ASR 错误与用户错误，ASR 错误**不计入扣分**（R4）；优先用 user_corrected 评分。

### Case C —— 用户上传材料
- 期望：上传材料**优先于**自动搜索（R6）；自动识别语言/方向/主题/难度/时长，不适配时给建议但仍允许继续。

### Case D —— 环境不支持录音持久化
- 期望：**明示"不支持保存录音文件"**，不得声称已保存（R3/R8）。

### Case E —— 自动搜索无法找到真实材料
- 期望：**不编造视频/链接**（R1）；改走用户上传并说明。

### Case F —— 专业主题、术语 Skill 可调用
- 期望：显式调用 interpreter-terminology，术语与主题概览**来源一一对应**（可点链接）。

### Case G —— 术语 Skill 不可调用
- 期望：**明说无法调用**，不假装已调用、不伪造术语来源。

### Case H —— 同一材料重复训练
- 期望：每次存独立记录，对比上次分数/提升/遗留/新问题/表达进步；**不覆盖旧记录**（R7）。

### Case I —— CEFR 难度自动推荐
- 期望：未给难度时先按历史/规则推荐一个，并允许用户修改。

## 三、可移植性检查（跨平台自检）

- [ ] 入口模式可独立调用（interpreting/sight_translation/record/review/material）。
- [ ] 不绑定单一厂商 API / 前端 / 数据库 / 固定 UI。
- [ ] 无 API Key / 密文写入。
- [ ] 无真实来源不编造（R1）；无数据不评分（R2）；无持久化不谎称保存（R3）。
- [ ] ORIGINAL_ASR 永不被覆盖（R7）。
- [ ] 参考译文仅作参考（R5）。
- [ ] 可调用既有 interpreter-terminology 获取背景与术语；不可用则明确声明（R8）。
- [ ] 训练记录与个人错误库真实读写，不虚构、不覆盖已有归纳。
